运行时

Bun 优先，构建产物兼容 Node.js。build.ts 自动后处理 import.meta.require，让产物能在两套运行时下都能跑。

渲染层

Ink + React 终端 UI。packages/@ant/ink 是 fork 的内部版本，149 个组件，支持 7 个主题变体、89+ 语义色板。

状态层

Zustand 风格 store + 模块级单例。AppStateStore 管理会话级状态，bootstrap/state.ts 管全局单例。

工程化

Bun workspaces + 15 个内部包。React Compiler 全量启用，构建时自动产出 memoization 代码。

AGENT LOOP

会话循环与流式调度

每一次用户输入背后都是一个完整的状态机：消息发出 → 模型流式响应 → 工具调用 → 结果回喂 → 直到模型停止请求工具为止。

01

输入归一化

PromptInput 收集多模态输入（文本、图片、剪贴板），合并系统注入的上下文，构成一条 user message。

02

System Prompt 组装

context.ts 拼装系统提示：git 状态、当前时间、CLAUDE.md 内容、记忆文件、用户身份信息。

03

流式 API 调用

services/api/claude.ts 走 Anthropic SDK 流接口，处理 BetaRawMessageStreamEvent，按事件增量更新 UI。

04

工具调用解析

模型返回 tool_use 块时进入工具流水线：权限校验 → 用户审批（如需）→ 实际执行 → 结果整理。

05

结果回喂

工具执行结果以 tool_result 形式追加到对话，触发下一轮 API 调用。这是 Agent Loop 的"反馈环"核心。

06

压缩与持久化

QueryEngine 监控 token 使用，触发自动压缩、文件历史快照、归因记录、turn 级账本管理。

PERMISSION MODEL

多层权限系统

Claude Code 把"AI 能在你机器上做什么"做成了一个分层、可配置、可中断的决策模型。

default

每次工具调用都征求用户同意。安全网最强，节奏最慢。

acceptEdits

编辑类操作（FileEdit / FileWrite）自动允许，仍拦截 Shell 等高风险工具。

bypassPermissions

所有工具自动允许。仅在沙箱、CI 等隔离环境下使用。

plan

只读模式。模型可以分析、规划，但禁止任何修改性操作。

autoAccept

auto-mode 下临时进入：批准条件由配置规则决定，可配合 hooks 做精细控制。

readOnly

面向 sub-agent 的进一步收紧：只允许读类工具调用，子代理不能写盘。

权限决策流水线

  1. 工具的 needsPermissions() 判断是否需要询问
  2. 查询当前会话的 permission mode + 已存配置规则
  3. 命中规则 → 直接放行 / 拒绝；未命中 → 进入用户审批 UI
  4. 用户决定后（Allow / Allow & Remember / Deny）持久化或一次性应用
  5. hooks 系统可以在任意阶段拦截、改写、终止

MULTI-AGENT

子代理与协调

主 agent 不是孤军奋战。Agent 工具能 fork 出独立上下文的子代理，用于并行探索、独立审查、长任务分发。

Agent Tool

主 agent 把"找文件 / 写代码 / 跑命令"等任务委派给子代理。子代理拥有独立 context window，结果以单条消息回流。

Subagent Types

内置类型：Explore（搜索）、Plan（架构设计）、Code Reviewer（独立评审）等。每种 type 有专门的 system prompt + 工具集。

Background Agents

BG_SESSIONS 启用后，可用 --bg 启动后台会话，ps / logs / attach / kill 命令管理。适合长任务。

COORDINATOR_MODE

多 worker 编排模式。一个 coordinator 拆分任务、分发给多个 worker，最后 merge 结果。

Fork Render

UI 层支持 fork 消息渲染：从某条历史消息开新分支继续对话，便于实验性提示。

ACP 协议

Agent Client Protocol：让外部 agent 通过 WebSocket 接入，把 Claude Code 当成 backend 使用。

CONTEXT MANAGEMENT

上下文管理

长会话最大的敌人是 token 上限。Claude Code 的上下文管理由四块协作完成：注入、压缩、记忆、缓存。

系统提示注入

  • git status & branch
  • 项目级 CLAUDE.md（全层级合并）
  • 用户级 ~/.claude/CLAUDE.md
  • 当前时间、CWD、平台信息

自动压缩

token 占用接近上限时触发：保留最近若干 turn + 摘要早期消息。HISTORY_SNIP feature 提供更细粒度的裁剪。

记忆系统

EXTRACT_MEMORIES 在每个 turn 结束抽取关键事实写入 memory。LODESTONE 做向量召回，避免全量带入。

Prompt Cache

系统提示、工具定义、稳定的早期消息打 cache 标记。每次请求后自动检测命中率，低于阈值会黄色警告。

DESIGN PRINCIPLES

设计思想

从源码反推 Claude Code 团队的几条工程取舍。

1. 终端是一等公民

选 Ink 而非 Web UI，意味着在 React 编程模型下处理终端的所有怪癖：宽字符、ANSI、键盘事件、resize。换来的是和现代 Web 开发完全一致的开发体验，并且能跑在任何 SSH 环境里。

2. 工具是显式的、可审计的

每个工具都是一个独立模块：schema、permission、UI 渲染、result formatter 全在一处。新增工具不需要改主循环，主循环也不知道工具的具体行为。这套约定让 AI 行为可被人类逐步审查。

3. 流式优于批量

API、工具结果、UI 更新全部走流。streaming 不只是"打字效果"——它是 Agent Loop 中实现"早停"、"中断"、"渐进决策"的基础。

4. 兼容层是适配器，不是分支

OpenAI / Gemini / Grok 三套兼容层都把第三方协议转成 Anthropic 内部格式，下游代码完全不改。新增协议只加适配器，不动核心。

5. Feature Flag 优于 if-else

34 个 feature flag 由 bun:bundle 在构建期内联，不影响运行时性能。实验功能与稳定路径并存，关闭的功能完全不进产物。

6. 文档即源码注释

仓库里有大量 docs/features/*.mdx 与代码同步演进。新功能进 PR 时往往附带 200+ 行调研文档——这是 AI 协作时代的"白皮书"工作流。
